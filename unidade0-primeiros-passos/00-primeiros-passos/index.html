    0. Primeiros passos em programação¶

    Este capítulo é para quem nunca programou. Ele vem antes da primeira aula, e você estuda sozinho, no seu ritmo: leia com calma, rode cada exemplo e faça o caderno de estudo do fim. São umas quatro a seis horas, que dá para dividir em dois ou três dias.

    No fim, você vai saber o que é um programa, guardar valores em variáveis, fazer o programa decidir (if) e repetir (while e for), e ler o formato de função que todos os exercícios do curso usam. É o que a primeira aula dá como sabido.

    Se telecomunicações também é novidade para você, leia depois A rede da Maré Net: ela explica, sem fórmula, os termos que aparecem nos exemplos (dBm, OLT, alarme, NOC…). Por enquanto basta saber que potência é a força do sinal que chega pela fibra, medida em dBm, e que, nessa escala, os números são negativos: quanto mais negativo, mais fraco. −20 dBm é um sinal bom; −28 dBm é um sinal fraco demais.

    Como estudar este capítulo¶

    Você não precisa instalar nada. Abra o Google Colab, crie um caderno novo e, para cada exemplo:

    1. leia o código e tente adivinhar o que ele vai mostrar;
    2. digite o código numa célula (digitar, e não colar, é o que faz os dedos e a cabeça aprenderem);
    3. rode com Shift+Enter e compare com a saída mostrada aqui;
    4. mude alguma coisa — um número, um texto — e rode de novo.

    O passo 4 é o mais importante. Programar se aprende como se aprende a andar de bicicleta: lendo sobre o assunto dá para entender a ideia, mas o equilíbrio só vem tentando, e errando.

    O que é um programa¶

    Um programa é uma lista de instruções que o computador segue, uma de cada vez, de cima para baixo.

    # Um programa e uma receita: as linhas rodam de cima para baixo, uma de cada vez.
print("1. abrir o chamado")
print("2. conferir o equipamento")
print("3. fechar o chamado")

    1. abrir o chamado
2. conferir o equipamento
3. fechar o chamado

    💡 Pense assim: uma receita de bolo

    Uma receita diz o que fazer e em que ordem: primeiro bata os ovos, depois junte a farinha, depois leve ao forno. Um programa é igual, com uma diferença importante: o computador segue a receita ao pé da letra. Ele não adivinha o que você quis dizer, não pula um passo que parece óbvio e não corrige um erro de digitação. Se a receita estiver errada, o bolo sai errado — e a culpa é da receita.

    print(...) é a instrução que mostra alguma coisa na tela. O que vai entre aspas é mostrado exatamente como está escrito. As linhas que começam com # são comentários: o Python ignora tudo o que vem depois do #, e eles servem para explicar o código a quem lê.

    Variáveis: nomes que guardam valores¶

    Um programa precisa guardar valores para usá-los depois: quantos clientes uma central atende, a potência medida agora há pouco. Para isso existem as variáveis.

    # Uma variavel e um nome que guarda um valor.
clientes = 30
print(clientes)

# O mesmo nome pode receber um valor novo: o antigo e descartado.
clientes = 31
print(clientes)

# Primeiro o lado direito e calculado (31 + 1), depois o resultado e guardado.
clientes = clientes + 1
print(clientes)

    30
31
32

    💡 Pense assim: uma etiqueta numa caixa

    clientes = 30 cola a etiqueta clientes numa caixa e põe o valor 30 dentro. Toda vez que o programa escreve clientes, ele abre a caixa e usa o que está lá. Guardar outro valor com o mesmo nome troca o conteúdo da caixa: o 30 é jogado fora e o 31 entra no lugar.

    O sinal = não quer dizer "é igual", como na matemática. Ele quer dizer "guarde": calcule o que está à direita e guarde no nome que está à esquerda. Por isso clientes = clientes + 1, que não faz sentido como equação, faz todo sentido como instrução: pegue o valor atual de clientes (31), some 1 e guarde o resultado (32) de volta em clientes.

    O nome de uma variável pode ter letras, números e o sublinhado _, mas não pode começar com número nem ter espaço ou acento. Escolha nomes que digam o que está guardado: potencia_dbm diz muito mais do que p.

    Tipos: número, texto e verdadeiro ou falso¶

    Todo valor tem um tipo, que diz que espécie de dado ele é. No começo, quatro tipos resolvem quase tudo:

    portas = 16              # int: numero inteiro
potencia = -21.4         # float: numero com casas decimais (ponto, nao virgula)
nome = "OLT-CENTRO-01"   # str: texto, sempre entre aspas
no_ar = True             # bool: verdadeiro (True) ou falso (False)

print(type(portas))
print(type(potencia))
print(type(nome))
print(type(no_ar))

# O tipo muda o que o + faz: com numeros, soma; com textos, emenda.
print(3 + 4)
print("3" + "4")

    <class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
7
34
    Tipo O que guarda Exemplos
    int número inteiro 16, 0, -3
    float número com casas decimais -21.4, 99.5
    str texto (string), sempre entre aspas "OLT-CENTRO-01", "34"
    bool verdadeiro ou falso True, False

    Duas coisas pegam quem está começando:

    • a casa decimal é marcada com ponto, e não com vírgula: -21.4;
    • "34" entre aspas é texto, e não número. Por isso "3" + "4" dá "34": com textos, o + emenda um no outro, como duas peças de trem.

    💡 Pense assim: a unidade de medida

    Na conta da padaria, "3 pães + 4 pães" dá 7 pães, mas "3 pães + 4 reais" não dá nada que faça sentido. O tipo é a "unidade" do valor em Python: ele decide o que cada operação faz com o valor e quais operações são permitidas.

    Quando dá erro: lendo a mensagem¶

    Errar é a parte normal de programar — quem programa há vinte anos erra todo dia. O que muda com a experiência é a velocidade de ler a mensagem de erro e achar a causa. Um nome digitado errado:

    # Um nome digitado errado so aparece quando a linha roda.
potencia_dbm = -21.4
print(potencia_dmb)

    NameError: name 'potencia_dmb' is not defined. Did you mean: 'potencia_dbm'?

    A mensagem completa tem várias linhas; leia de baixo para cima. A última linha diz o tipo do erro (NameError: um nome que não existe) e o que aconteceu. Um pouco acima, a mensagem mostra a linha do programa em que o erro apareceu. Aqui, o Python ainda sugere a correção: Did you mean: 'potencia_dbm'? ("você quis dizer…?").

    💡 Pense assim: a luz no painel do carro

    Quando acende uma luz no painel, ela não diz "o carro quebrou": diz qual sistema tem problema. A mensagem de erro é essa luz. Não se assuste com o vermelho — leia o que está escrito, porque quase sempre a resposta está lá.

    Comparações: perguntas de sim ou não¶

    Para decidir alguma coisa, o programa primeiro precisa perguntar. As comparações são perguntas cuja resposta é True (sim) ou False (não):

    potencia = -24.0

print(potencia < -27)     # a potencia esta abaixo de -27?
print(potencia > -27)     # esta acima de -27?
print(potencia == -24.0)  # dois sinais de igual: PERGUNTA se e igual
print(potencia != -24.0)  # e diferente?

    False
True
True
False
    Operador Pergunta
    < / > é menor? / é maior?
    <= / >= é menor ou igual? / é maior ou igual?
    == é igual? (dois sinais de igual)
    != é diferente?

    Atenção aos números negativos: −24 é maior que −27, porque está mais perto do zero (e o sinal de −24 dBm é mais forte que o de −27 dBm). Pense no termômetro: −24 °C é menos frio que −27 °C.

    if: decidir¶

    O if ("se") executa um bloco de instruções só se a pergunta der True:

    potencia = -28.5

if potencia < -27:
    print("ALERTA: sinal fraco")
    print("abrir chamado para a equipe de campo")
print("fim da verificacao")

    ALERTA: sinal fraco
abrir chamado para a equipe de campo
fim da verificacao

    Repare em três detalhes, porque o Python exige todos eles:

    • a linha do if termina com dois-pontos :;
    • as linhas que pertencem ao if ficam recuadas quatro espaços (no Colab, a tecla Tab faz isso). Esse recuo se chama indentação, e é ele que diz o que está "dentro" do if;
    • a primeira linha sem recuo (print("fim da verificacao")) já está fora do if: ela roda sempre, dê a pergunta True ou False.

    Troque -28.5 por -20.0 e rode de novo: as duas linhas do alerta somem, e só o "fim da verificacao" aparece.

    💡 Pense assim: o porteiro da festa

    O porteiro olha a pulseira de cada pessoa: se tem pulseira, ela entra. Quem não tem, não entra, e a festa continua do mesmo jeito. O if é o porteiro, e o bloco recuado é o que acontece só com quem passou pela porta.

    Os dois erros mais comuns com o if:

    # Um sinal de igual guarda; dois perguntam. No if, a pergunta e ==.
potencia = -28.0
if potencia = -28.0:
    print("igual")

    SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?

    Um = sozinho guarda; para perguntar se é igual, são dois: ==. O Python até sugere a troca. E esquecer o recuo:

    # O que esta "dentro" do if precisa estar recuado.
potencia = -28.0
if potencia < -27:
print("sinal fraco")

    IndentationError: expected an indented block after 'if' statement on line 3

    "expected an indented block" quer dizer "eu esperava um bloco recuado": depois de um if com dois-pontos, tem de vir pelo menos uma linha recuada.

    elif e else: mais de um caminho¶

    Muitas vezes a decisão tem mais de duas saídas. Uma potência pode estar boa, pedir atenção ou estar crítica:

    potencia = -26.0

if potencia >= -25:
    print("bom")
elif potencia >= -27:
    print("atencao")
else:
    print("critico")

    atencao
    • if: a primeira pergunta;
    • elif ("senão, se"): só é perguntado se as de cima deram False;
    • else ("senão"): o que sobra, quando nenhuma pergunta deu True. Ele não tem pergunta.

    O Python pergunta de cima para baixo e para na primeira que der True: só um dos blocos roda. Com −26: é >= -25? Não. É >= -27? Sim → "atencao", e o resto é pulado. Teste com −20, −26 e −30 e veja cada caminho.

    💡 Pense assim: a triagem do pronto-socorro

    Na triagem, o enfermeiro pergunta em ordem: "é caso de risco de vida?" → vermelho. "Senão, é urgente?" → amarelo. "Senão" → verde. Cada paciente sai com uma cor só, e a ordem das perguntas importa. O NOC — a central que vigia a rede do provedor — classifica os alarmes do mesmo jeito.

    and, or e not¶

    Para juntar perguntas:

    potencia = -28.0
em_servico = True

# and: as duas condicoes precisam ser verdadeiras.
print(em_servico and potencia < -27)

# or: basta uma das duas.
print(potencia < -27 or potencia > -8)

# not: inverte.
print(not em_servico)

if em_servico and potencia < -27:
    print("cliente ativo com sinal fraco: abrir chamado")

    True
True
False
cliente ativo com sinal fraco: abrir chamado
    • a and b ("e"): True só se as duas forem True;
    • a or b ("ou"): True se pelo menos uma for True;
    • not a ("não"): inverte — True vira False, e o contrário.

    💡 Pense assim: a regra do estacionamento

    "Pode estacionar quem é morador e tem vaga": precisa das duas coisas. "Entra de graça quem é criança ou idoso": basta uma. O and é exigente; o or é generoso.

    while: repetir enquanto¶

    Agora, repetir. O while ("enquanto") repete um bloco enquanto a pergunta der True. Cada vez que o sinal passa por um divisor (splitter) que o reparte em dois, ele perde metade da potência — em dBm, perder metade é perder 3. Quantos divisores cabem antes de o sinal ficar fraco demais?

    # Cada divisor de sinal (splitter) 1:2 corta a potencia pela metade: -3 dB.
# Quantos divisores cabem antes de o sinal chegar a -27 dBm?
potencia = -15.0
divisores = 0

while potencia > -27:
    potencia = potencia - 3
    divisores = divisores + 1
    print("com", divisores, "divisores:", potencia, "dBm")

print("total:", divisores)

    com 1 divisores: -18.0 dBm
com 2 divisores: -21.0 dBm
com 3 divisores: -24.0 dBm
com 4 divisores: -27.0 dBm
total: 4

    A cada volta, o Python faz a pergunta (potencia > -27?). Se der True, roda o bloco recuado e volta para perguntar de novo. Quando a potência chega a −27, a pergunta dá False (−27 não é maior que −27), e o programa segue para a linha depois do bloco.

    💡 Pense assim: encher o balde

    "Enquanto o balde não chegar na marca, jogue mais uma caneca de água." Você confere a marca antes de cada caneca, e para quando chega nela. Se você esquecesse de jogar a água, conferiria a marca para sempre.

    É por isso que o bloco do while precisa mudar alguma coisa que a pergunta usa (aqui, potencia = potencia - 3). Sem essa linha, a potência nunca muda, a pergunta dá True para sempre e o programa não termina: é o laço infinito. Se acontecer, pare a célula no botão ■ do Colab.

    divisores = divisores + 1 é um contador: ele começa em zero antes do laço e ganha 1 a cada volta. Você vai usar esse padrão o curso inteiro.

    for: repetir para cada item¶

    O for ("para cada") repete o bloco uma vez para cada item de uma sequência. A sequência mais simples é o range, que gera números:

    # range(4) produz 0, 1, 2 e 3: quatro voltas, comecando do zero.
for volta in range(4):
    print("volta", volta)

# range(1, 5) comeca no 1 e para ANTES do 5.
for porta in range(1, 5):
    print("testando a porta", porta)

    volta 0
volta 1
volta 2
volta 3
testando a porta 1
testando a porta 2
testando a porta 3
testando a porta 4
    • em for volta in range(4), a variável volta vale 0 na primeira volta, 1 na segunda, e assim até 3. São quatro voltas, e a contagem começa no zero — um costume da programação que você vai encontrar em todo lugar;
    • range(1, 5) começa no 1 e para antes do 5: 1, 2, 3 e 4.

    O for também percorre uma lista de valores escrita entre colchetes:

    # O for tambem percorre uma lista de valores pronta, um de cada vez.
for potencia in [-21.4, -28.0, -19.5]:
    print("medicao:", potencia, "dBm")
print("fim")

    medicao: -21.4 dBm
medicao: -28.0 dBm
medicao: -19.5 dBm
fim

    💡 Pense assim: a chamada na sala de aula

    O professor pega a lista de presença e, para cada nome da lista, chama o nome e marca a presença. Ele não precisa saber de antemão quantos alunos são: começa no primeiro, vai até o último e para. O for é essa chamada; a variável (potencia) é o nome da vez.

    while ou for? Use for quando você sabe sobre o que vai repetir: cada item de uma lista, cada número de 1 a 16. Use while quando você não sabe quantas voltas serão, só quando parar — como no balde e nos divisores. No curso, o for aparece muito mais.

    Juntando tudo¶

    Um for com um if dentro e um contador — o formato de boa parte dos programas que você vai escrever. Das medições de potência abaixo, quantas estão abaixo do limite de −27 dBm?

    medicoes = [-21.4, -28.0, -19.5, -27.3, -24.8]
abaixo = 0

for potencia in medicoes:
    if potencia < -27:
        abaixo = abaixo + 1
        print(potencia, "-> abaixo do limite")

print("total abaixo do limite:", abaixo)

    -28.0 -> abaixo do limite
-27.3 -> abaixo do limite
total abaixo do limite: 2

    Leia o recuo com cuidado, porque ele conta a história do programa:

    • abaixo = 0 está antes do for: roda uma vez só;
    • o if está dentro do for (quatro espaços): roda uma vez para cada medição;
    • as duas linhas depois do if estão dentro do if (oito espaços): rodam só para as medições abaixo do limite;
    • o último print está fora de tudo: roda uma vez, no fim.

    Mude um recuo e o programa faz outra coisa. Experimente pôr o último print com quatro espaços e veja o total aparecer a cada volta.

    Uma primeira função¶

    Todos os exercícios do curso têm o mesmo formato: uma função para você completar. Uma função é um pedaço de programa com nome, que recebe valores, faz uma conta e devolve o resultado:

    def margem(potencia, sensibilidade):
    """Devolve quantos dB a potencia esta acima da sensibilidade."""
    resultado = potencia - sensibilidade
    return resultado


print(margem(-21.5, -27))    # usa a funcao e mostra o que ela devolveu

folga = margem(-26.0, -27)   # guarda o que ela devolveu numa variavel
print(folga)

    5.5
1.0
    • def margem(potencia, sensibilidade): define a função: o nome dela é margem, e ela recebe dois valores, que dentro dela se chamam potencia e sensibilidade;
    • a linha entre aspas triplas diz em português o que a função faz;
    • return resultado devolve o resultado para quem chamou a função;
    • definir não executa nada: a função só roda quando alguém a chama, como em margem(-21.5, -27). Aí potencia vale −21,5, sensibilidade vale −27, e a chamada inteira "vira" o valor devolvido, 5,5.

    💡 Pense assim: a máquina de café

    Você põe a cápsula e a água (os valores que a função recebe), a máquina faz o trabalho lá dentro, e sai o café (o que ela devolve). Você não precisa ver o que acontece dentro para usar a máquina, e pode usá-la quantas vezes quiser, com cápsulas diferentes.

    return e print não são a mesma coisa. O print só mostra na tela; o return entrega o valor para o programa continuar usando — guardar numa variável, comparar, somar. Os testes automáticos dos exercícios conferem o que a função devolve: uma função que só faz print e esquece o return devolve None ("nada"), e o teste reprova. O capítulo 4 volta às funções com calma.

    Onde isso é usado de verdade¶

    Por trás de todo sistema de monitoramento de rede há um laço e um if. O Zabbix, um dos sistemas de monitoramento mais usados em provedores, repete a coleta de cada equipamento de tempos em tempos (o laço) e, a cada valor coletado, testa uma condição de disparo (trigger) — "a potência está abaixo de −27 dBm?". Quando a condição dá verdadeira, ele abre um alarme, com a severidade decidida por condições em sequência, como no if/elif/else deste capítulo. O exemplo de "Juntando tudo" é uma versão pequena desse sistema.

    Resumo¶

    • Um programa é uma lista de instruções executadas de cima para baixo, ao pé da letra.
    • nome = valor guarda o valor no nome; = é "guarde", == é "é igual?".
    • Tipos básicos: int, float (com ponto), str (entre aspas) e bool (True/False).
    • A mensagem de erro se lê de baixo para cima: o tipo do erro e a linha.
    • if / elif / else escolhem um caminho; and, or e not juntam perguntas.
    • while repete enquanto a pergunta for verdadeira; for repete para cada item.
    • O recuo (quatro espaços) diz o que está dentro de cada bloco.
    • def cria uma função, que recebe valores e devolve o resultado com return.
