    10. Dataclasses: o equipamento como um tipo¶

    Um equipamento tem nome, IP, número de portas e um estado. Até aqui ele morou em listas paralelas (uma lista de nomes, outra de IPs) ou num dicionário. Os dois funcionam — até o dia em que não funcionam, sem avisar.

    Este capítulo apresenta a dataclass: um jeito de dizer ao Python "um equipamento é isto: estes campos, destes tipos". O equipamento passa a ser um tipo, como str e list — e o Python passa a reclamar quando você erra o nome de um campo.

    O problema das listas paralelas e dos dicionários soltos¶

    # Listas paralelas: o i-esimo nome vai com o i-esimo IP -- enquanto ninguem mexer.
nomes = ["OLT-CENTRO-01", "ONU-SUL-4512", "OLT-NORTE-02"]
ips = ["10.0.1.10", "10.0.3.47", "10.0.2.10"]
print(nomes[1], ips[1])

nomes.sort()                      # alguem ordenou so uma das listas...
print(nomes[1], ips[1])           # ...e o nome foi parar em outro IP

# Dicionario: uma chave digitada errado nao da erro nenhum com .get().
equipamento = {"nome": "OLT-CENTRO-01", "portas": 16}
print(equipamento.get("porta", 0))

    ONU-SUL-4512 10.0.3.47
OLT-NORTE-02 10.0.3.47
0

    Dois defeitos, nenhum com mensagem de erro:

    • nas listas paralelas, o que liga o nome ao IP é só a posição. Ordenar uma lista sem ordenar a outra desalinha tudo — e agora a OLT-NORTE-02 "tem" o IP da ONU;
    • no dicionário, "porta" e "portas" são duas chaves diferentes, e o get com valor padrão devolve 0 para a chave errada em vez de avisar. Um total de portas calculado assim sai errado por meses.

    O que falta nos dois é alguém que saiba quais campos um equipamento tem.

    💡 Pense assim: as duas folhas soltas

    Imagine os nomes dos alunos numa folha e os telefones em outra, na mesma ordem. Se alguém põe a folha dos nomes em ordem alfabética e esquece a outra, cada nome passa a ter o telefone de outra pessoa — e nada no papel avisa. É o defeito das listas paralelas. O dicionário resolve a ligação, mas aceita qualquer rótulo, até um escrito errado.

    @dataclass¶

    from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    ip: str
    portas: int


olt = Equipamento("OLT-CENTRO-01", "10.0.1.10", 16)
print(olt)
print(olt.nome)
print(olt.portas + 8)

# Passar pelo nome do campo deixa a chamada legivel -- e a ordem deixa de importar.
outra = Equipamento(ip="10.0.1.10", nome="OLT-CENTRO-01", portas=16)
print(outra == olt)

# Atribuir num campo troca o valor, como numa variavel.
olt.portas = 24
print(olt)

    Equipamento(nome='OLT-CENTRO-01', ip='10.0.1.10', portas=16)
OLT-CENTRO-01
24
True
Equipamento(nome='OLT-CENTRO-01', ip='10.0.1.10', portas=24)

    Leia por partes:

    • from dataclasses import dataclass traz a ferramenta, da biblioteca padrão;
    • class Equipamento: cria um tipo novo chamado Equipamento (nomes de tipo começam com maiúscula, por convenção);
    • @dataclass, a linha logo acima, é o que transforma a lista de campos em algo utilizável — sem ela, a classe não saberia receber os valores;
    • cada campo é nome: tipo. O tipo documenta o que se espera, mas não é conferido pelo Python: é para quem lê;
    • Equipamento("OLT-CENTRO-01", "10.0.1.10", 16) cria um equipamento — um objeto daquele tipo —, com os valores na ordem dos campos;
    • olt.nome lê um campo, com ponto, no lugar do olt["nome"] do dicionário.

    💡 Pense assim: o modelo da ficha e as fichas preenchidas

    A classe é o modelo da ficha em branco, impresso na gráfica: diz quais campos existem (nome, IP, portas) e em que ordem. Cada objeto é uma ficha preenchida: Equipamento("OLT-CENTRO-01", "10.0.1.10", 16) pega uma ficha nova e preenche. Com um modelo, dá para preencher quantas fichas quiser — e ninguém consegue inventar um campo que não está impresso no modelo.

    De graça, a dataclass traz duas coisas: o print mostra todos os campos com os nomes, e == compara campo a campo. Criar passando o nome de cada campo (nome=..., ip=...) é mais longo, mas deixa a chamada legível e a ordem deixa de importar.

    Esquecer um campo, agora, é erro na hora de criar:

    from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    ip: str
    portas: int


olt = Equipamento("OLT-CENTRO-01", "10.0.1.10")   # faltou o numero de portas

    TypeError: Equipamento.__init__() missing 1 required positional argument: 'portas'

    Valor padrão¶

    Um campo pode ter valor padrão, como um parâmetro de função (capítulo 4):

    from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    ip: str
    portas: int
    em_servico: bool = True         # valor padrao: quem nao disser, esta em servico


olt = Equipamento("OLT-CENTRO-01", "10.0.1.10", 16)
reserva = Equipamento("OLT-NORTE-02", "10.0.2.10", 8, em_servico=False)
print(olt.em_servico)
print(reserva)

    True
Equipamento(nome='OLT-NORTE-02', ip='10.0.2.10', portas=8, em_servico=False)

    A regra é a mesma das funções: os campos com padrão vêm depois dos sem padrão. Ao contrário, o Python recusa a classe:

    from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    em_servico: bool = True
    portas: int               # campo sem padrao depois de um com padrao

    TypeError: non-default argument 'portas' follows default argument 'em_servico'

    Métodos: a função que mora junto do dado¶

    A margem de um enlace é uma conta que só faz sentido para um enlace. Em vez de uma função solta que recebe o enlace, ela pode morar dentro da classe — é um método:

    📡 Na rede: potência recebida e sensibilidade

    potencia_rx é a potência que chega ao receptor (rx é a abreviação de recepção; tx, de transmissão). A sensibilidade é a menor potência que o receptor ainda entende — nas ONUs da Maré Net, −27 dBm. A margem é a folga entre as duas: se é positiva, o enlace fecha (funciona); se é negativa, o sinal chega fraco demais. Veja Atenuação, sensibilidade e margem.

    from dataclasses import dataclass


@dataclass
class Enlace:
    nome: str
    potencia_rx: float
    sensibilidade: float = -27.0

    def margem(self):
        """Folga do enlace, em dB."""
        return round(self.potencia_rx - self.sensibilidade, 2)

    def fecha(self):
        """Diz se chega potencia suficiente."""
        return self.margem() >= 0


sul = Enlace("ONU-SUL-4512", -21.4)
leste = Enlace("ONU-LESTE-77", -28.1)
print(sul.margem(), sul.fecha())
print(leste.margem(), leste.fecha())

# O metodo e uma funcao: chamada pelo objeto, ele chega como self.
print(Enlace.margem(sul))

    5.6 True
-1.1 False
5.6
    • o método é um def escrito dentro da classe, com recuo;
    • o primeiro parâmetro se chama self e é o objeto da vez: em sul.margem(), self é o sul; em leste.margem(), é o leste. Quem passa o self é o próprio Python — por isso a chamada tem parênteses vazios;
    • dentro do método, os campos se leem por self.potencia_rx;
    • um método pode chamar outro: fecha usa self.margem().

    💡 Pense assim: “este aqui”

    Numa fila de conferência de documentos, o fiscal diz a cada pessoa: "mostre o seu documento". A frase é a mesma para todo mundo, mas "o seu" muda conforme quem está na frente dele. O self é esse "o seu": o método é escrito uma vez só, e o self passa a ser o objeto que está sendo atendido naquela chamada.

    A última linha mostra que não há mágica: sul.margem() é o mesmo que Enlace.margem(sul) — uma função comum, que recebe o enlace como primeiro argumento. É a mesma coisa que você já fazia com texto.upper(): upper é um método de str.

    Lista de objetos¶

    Um inventário vira uma lista de equipamentos, e os padrões da Unidade 1 continuam iguais:

    from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    tipo: str
    portas: int
    em_servico: bool = True


inventario = [
    Equipamento("OLT-CENTRO-01", "OLT", 16),
    Equipamento("ONU-SUL-4512", "ONU", 1),
    Equipamento("OLT-NORTE-02", "OLT", 8, em_servico=False),
    Equipamento("OLT-SUL-03", "OLT", 24),
]

# Os padroes de sempre -- com e.portas no lugar de e["portas"].
total = 0
for e in inventario:
    if e.em_servico:
        total = total + e.portas
print(total)

olts = []
for e in inventario:
    if e.tipo == "OLT":
        olts.append(e.nome)
print(olts)


def portas_do_equipamento(e):
    """Criterio de ordenacao: o numero de portas."""
    return e.portas


maior = sorted(inventario, key=portas_do_equipamento, reverse=True)[0]
print(maior.nome, maior.portas)

    41
['OLT-CENTRO-01', 'OLT-NORTE-02', 'OLT-SUL-03']
OLT-SUL-03 24

    Compare com a lista de dicionários do capítulo 6: o acumulador, o filtro e o sorted com key= são os mesmos. Muda só o acesso — e.portas no lugar de e["portas"]. E o nome do tipo, Equipamento, diz o que há na lista sem precisar abrir um item para ver.

    Do arquivo para o objeto¶

    Dado vem de fora como texto, JSON ou CSV. O ponto de entrada é o lugar certo para construir os objetos — e para converter os tipos uma vez só:

    import json
from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    ip: str
    portas: int
    em_servico: bool = True


texto = """
[
  {"nome": "OLT-CENTRO-01", "ip": "10.0.1.10", "portas": "16", "em_servico": true},
  {"nome": "ONU-SUL-4512", "ip": "10.0.3.47", "portas": "1", "em_servico": false}
]
"""

# Cada dicionario vira um objeto, construido campo a campo -- e a conversao de
# tipo (as portas vieram como texto) acontece aqui, uma vez so.
inventario = []
for d in json.loads(texto):
    e = Equipamento(
        nome=d["nome"],
        ip=d["ip"],
        portas=int(d["portas"]),
        em_servico=d["em_servico"],
    )
    inventario.append(e)

print(len(inventario))
print(inventario[0])
print(inventario[0].portas + inventario[1].portas)

    2
Equipamento(nome='OLT-CENTRO-01', ip='10.0.1.10', portas=16, em_servico=True)
17

    As portas vieram como texto ("16") no JSON. A conversão com int() acontece na construção; daí em diante, todo o programa recebe um Equipamento com portas numérico e ninguém mais precisa lembrar de converter. É a mesma ideia do parser do capítulo 9: normalizar na entrada.

    Atributo digitado errado¶

    E o defeito do começo do capítulo, agora com uma dataclass:

    from dataclasses import dataclass


@dataclass
class Equipamento:
    nome: str
    portas: int


olt = Equipamento("OLT-CENTRO-01", 16)
print(olt.porta)          # digitado errado: o objeto nao tem esse campo

    AttributeError: 'Equipamento' object has no attribute 'porta'. Did you mean: 'portas'?

    O Python sabe quais campos um Equipamento tem, e reclama na hora, na linha do erro — com sugestão de correção. Com o dicionário e o get, o mesmo engano virava um 0 silencioso no relatório.

    Compare as três formas de guardar o mesmo equipamento:

    listas paralelas dicionário dataclass
    o que liga os campos a posição as chaves o objeto
    campo digitado errado — passa em silêncio com get AttributeError na hora
    campo esquecido desalinha as listas passa em silêncio TypeError na criação
    conta que é do dado função solta função solta método

    Onde isso é usado de verdade¶

    As ferramentas de automação de rede representam equipamentos exatamente assim: como objetos com campos e métodos. No pyATS, da Cisco, o testbed carregado de um arquivo vira um conjunto de objetos Device, e device.parse("show version") é um método chamado no equipamento. No pynetbox, a biblioteca Python do NetBox, cada equipamento consultado na API chega como um objeto, e o nome se lê com device.name — o mesmo ponto deste capítulo.

    A própria dataclass é parte da biblioteca padrão desde o Python 3.7, proposta na PEP 557 justamente para o caso "uma classe que é, principalmente, um registro de campos". A documentação oficial traz o que ficou de fora aqui (campos imutáveis, conversão para dicionário, ordenação automática).

    Erros comuns deste capítulo¶

    Sintoma Causa provável
    TypeError: Equipamento() takes no arguments faltou o @dataclass acima da classe
    TypeError: ... missing 1 required positional argument um campo sem valor padrão não foi passado na criação
    TypeError: non-default argument ... follows default argument campo sem padrão depois de campo com padrão
    AttributeError: ... has no attribute nome de campo digitado errado — leia a sugestão no fim da mensagem
    TypeError: Enlace.margem() takes 0 positional arguments but 1 was given o método foi escrito sem o self
    NameError: name 'potencia_rx' is not defined dentro do método faltou o self. antes do nome do campo
    o total saiu concatenado, como "168" a conversão de tipo não foi feita na construção (int(...))

    Resumo¶

    • @dataclass + class Nome: + campo: tipo cria um tipo novo; cada valor criado é um objeto desse tipo.
    • Campo se lê e se altera com ponto: olt.portas.
    • Valor padrão como nas funções — e depois dos campos sem padrão.
    • Método é um def dentro da classe; self é o objeto da vez.
    • Lista de objetos: os mesmos padrões de laço, com e.campo.
    • Construa os objetos na entrada, convertendo os tipos uma vez só.
    • Campo digitado errado vira AttributeError na hora, e não um zero silencioso.
