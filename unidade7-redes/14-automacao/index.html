    14. Automação de equipamentos: o mesmo comando em N equipamentos¶

    O capítulo anterior perguntou a um sistema. Este pergunta aos próprios equipamentos: conecta em cada switch por SSH, roda um comando, lê a saída e monta o relatório. É o que um técnico faz à mão, equipamento por equipamento, abrindo um terminal para cada um — e é o que o script faz em segundos para cinquenta, sem esquecer nenhum e sem copiar errado.

    Não há equipamento de verdade no Colab, então os exemplos usam switches simulados (simuladores/equipamento_simulado.py), com a mesma interface da biblioteca Netmiko, a mais usada para isso em Python. O simulador responde a show version, show ip interface brief e show clock com saídas realistas — e dois dos cinco switches falham de propósito: um não responde e outro recusa a senha.

    Conectar e mandar um comando¶

    from simuladores.equipamento_simulado import ConnectHandler

# Abrir a "sessao SSH": o tipo de equipamento, o endereco e as credenciais.
conexao = ConnectHandler(
    device_type="cisco_ios",
    host="10.0.1.20",
    username="noc",
    password="marenet",
)

# send_command manda um comando e devolve a saida inteira, como texto.
saida = conexao.send_command("show version")
print(type(saida))
print(saida)

conexao.disconnect()

    • ConnectHandler(...) abre a sessão: o tipo de equipamento (que diz à biblioteca como falar com ele), o endereço e as credenciais;
    • send_command("show version") manda o comando e devolve a saída inteira, como texto — exatamente o que apareceria no terminal;
    • disconnect() fecha a sessão.

    A saída é uma str. Tudo o que o capítulo 9 ensinou sobre texto vale aqui: o equipamento responde em texto, e transformar texto em dado é trabalho do script.

    with: a conexão que fecha sozinha¶

    from simuladores.equipamento_simulado import ConnectHandler

# O mesmo with do open(): a conexao fecha sozinha ao sair do bloco.
dispositivo = {"device_type": "cisco_ios", "host": "10.0.2.20",
               "username": "noc", "password": "marenet"}

# **dispositivo passa cada chave do dicionario como um argumento com nome.
with ConnectHandler(**dispositivo) as conexao:
    print(conexao.send_command("show clock"))
    print(conexao.send_command("show ip interface brief"))

    O with é o mesmo do open() do capítulo 7: ao sair do bloco — inclusive por causa de um erro —, a conexão é fechada. Equipamento de rede aceita poucas sessões ao mesmo tempo; um script que abre e esquece acaba bloqueando o acesso da própria equipe.

    A outra novidade é o **dispositivo. Ele desempacota o dicionário em argumentos com nome: é o mesmo que escrever device_type="cisco_ios", host="10.0.2.20", .... Guardar os dados de cada equipamento num dicionário (vindo de um inventário) e passar com ** é a forma que se vê em todo código de automação.

    Da saída ao dado¶

    A saída do show ip interface brief é uma tabela em texto. Cada linha tem a interface, o IP, duas colunas de controle, o estado e o protocolo — e o estado pode ter espaço dentro (administratively down):

    saida = """Interface              IP-Address      OK? Method Status                Protocol
Vlan20                 10.0.2.20       YES manual up                    up
GigabitEthernet1/0/1   unassigned      YES manual up                    up
GigabitEthernet1/0/2   unassigned      YES manual administratively down down
GigabitEthernet1/0/3   unassigned      YES manual down                  down"""

estados = {}
for linha in saida.splitlines()[1:]:          # a primeira linha e o cabecalho
    interface, ip, ok, metodo, resto = linha.split(maxsplit=4)
    # "administratively down down": o estado pode ter espaco; o protocolo, nao.
    # rpartition e o partition que corta na ULTIMA ocorrencia.
    estado, _, protocolo = resto.rpartition(" ")
    estados[interface] = estado.strip()

print(estados)
em_uso = 0
for estado in estados.values():
    if estado == "up":
        em_uso = em_uso + 1
print(em_uso, "de", len(estados), "interfaces up")

    {'Vlan20': 'up', 'GigabitEthernet1/0/1': 'up', 'GigabitEthernet1/0/2': 'administratively down', 'GigabitEthernet1/0/3': 'down'}
2 de 4 interfaces up

    As ferramentas são as do capítulo 9: splitlines()[1:] pula o cabeçalho; split(maxsplit=4) separa as quatro primeiras colunas e deixa o resto inteiro; e rpartition(" ") — o partition que corta na última ocorrência — separa o protocolo (a última palavra) do estado (todo o resto). O strip() limpa os espaços de alinhamento.

    O coletor completo¶

    Agora as peças juntas: um laço sobre o inventário, a coleta de cada equipamento numa função que nunca levanta erro, e o resultado de cada um numa dataclass (capítulo 10).

    # O coletor completo: um laco sobre o inventario, falha por item, resultado por
# equipamento numa dataclass.
from dataclasses import dataclass

from simuladores.equipamento_simulado import (
    ConnectHandler,
    NetmikoAuthenticationException,
    NetmikoTimeoutException,
)

INVENTARIO = [
    {"nome": "SWITCH-CENTRO-01", "host": "10.0.1.20"},
    {"nome": "SWITCH-NORTE-02", "host": "10.0.2.20"},
    {"nome": "SWITCH-SUL-03", "host": "10.0.3.20"},
    {"nome": "SWITCH-LESTE-04", "host": "10.0.4.20"},
    {"nome": "SWITCH-OESTE-05", "host": "10.0.5.20"},
]


@dataclass
class Resultado:
    nome: str
    ok: bool
    versao: str = ""
    interfaces_up: int = 0
    erro: str = ""


def versao_de(saida):
    """A versao do sistema, tirada da saida do show version."""
    for linha in saida.splitlines():
        if "Version " in linha:
            _, _, depois = linha.partition("Version ")
            versao, _, _ = depois.partition(",")
            return versao
    return "?"


def interfaces_up(saida):
    """Quantas interfaces com estado up no show ip interface brief."""
    quantas = 0
    for linha in saida.splitlines()[1:]:
        resto = linha.split(maxsplit=4)[4]
        estado, _, protocolo = resto.rpartition(" ")
        if estado.strip() == "up":
            quantas = quantas + 1
    return quantas


def coleta(item):
    """Conecta num equipamento e devolve o Resultado -- nunca levanta erro."""
    try:
        with ConnectHandler(device_type="cisco_ios", host=item["host"],
                            username="noc", password="marenet", timeout=5) as conexao:
            versao = versao_de(conexao.send_command("show version"))
            up = interfaces_up(conexao.send_command("show ip interface brief"))
        return Resultado(item["nome"], True, versao, up)
    except NetmikoTimeoutException:
        return Resultado(item["nome"], False, erro="tempo esgotado")
    except NetmikoAuthenticationException:
        return Resultado(item["nome"], False, erro="senha recusada")


resultados = []
for item in INVENTARIO:
    resultados.append(coleta(item))

for r in resultados:
    if r.ok:
        print(f"{r.nome:<18}{r.versao:<12}{r.interfaces_up:>3} interfaces up")
for r in resultados:
    if not r.ok:
        print(f"{r.nome:<18}FALHOU: {r.erro}")

    SWITCH-CENTRO-01  15.2(7)E7     3 interfaces up
SWITCH-NORTE-02   15.2(7)E7     2 interfaces up
SWITCH-OESTE-05   15.2(4)E10    3 interfaces up
SWITCH-SUL-03     FALHOU: tempo esgotado
SWITCH-LESTE-04   FALHOU: senha recusada

    Leia a função coleta com atenção, porque ela é o coração de qualquer automação:

    • todo o trabalho com o equipamento fica dentro do try;
    • cada tipo de falha tem o seu except, e cada um devolve um Resultado com ok=False e o motivo — o laço nunca vê uma exceção;
    • o Resultado tem o mesmo formato para quem deu certo e para quem falhou, então o relatório é um laço simples sobre a lista.

    As duas falhas são as mais comuns do dia a dia: o equipamento que não responde (desligado, rota quebrada, firewall no caminho) e a senha recusada (credencial trocada e não atualizada no inventário). Sem o try, a primeira delas encerra a coleta:

    from simuladores.equipamento_simulado import ConnectHandler

# Um equipamento que nao responde: sem try, a coleta inteira para aqui.
ConnectHandler(device_type="cisco_ios", host="10.0.3.20", username="noc", password="marenet")

    simuladores.equipamento_simulado.NetmikoTimeoutException: TCP connection to device failed: 10.0.3.20

    Do resultado ao relatório¶

    Com os resultados numa lista, o capítulo 11 assume:

    import pandas as pd

# Os resultados da coleta, um dicionario por equipamento, viram uma tabela.
linhas = [
    {"nome": "SWITCH-CENTRO-01", "ok": True, "versao": "15.2(7)E7", "interfaces_up": 3, "erro": ""},
    {"nome": "SWITCH-NORTE-02", "ok": True, "versao": "15.2(7)E7", "interfaces_up": 2, "erro": ""},
    {"nome": "SWITCH-SUL-03", "ok": False, "versao": "", "interfaces_up": 0, "erro": "tempo esgotado"},
    {"nome": "SWITCH-LESTE-04", "ok": False, "versao": "", "interfaces_up": 0, "erro": "senha recusada"},
    {"nome": "SWITCH-OESTE-05", "ok": True, "versao": "15.2(4)E10", "interfaces_up": 3, "erro": ""},

tabela = pd.DataFrame(linhas)

# Quantos em cada versao -- a pergunta de quem planeja uma atualizacao de firmware.
print(tabela[tabela["ok"]]["versao"].value_counts())

    Com equipamentos de verdade¶

    O simulador tem a mesma interface da Netmiko, inclusive os nomes das exceções. Com equipamentos de verdade, o coletor muda uma linha — o import:

    from netmiko import (
    ConnectHandler,
    NetmikoAuthenticationException,
    NetmikoTimeoutException,
)

    e o pip install netmiko antes. O resto do código — o laço, o with, os except, a dataclass, o parser da saída — é o mesmo. Duas diferenças práticas: a senha não vai escrita no código (vem de uma variável de ambiente ou de um cofre de senhas), e o device_type precisa corresponder ao sistema do equipamento (cisco_ios, juniper_junos, huawei, mikrotik_routeros…).

    Comece pelos comandos de leitura

    Todo comando deste capítulo só lê (show ...). A Netmiko também envia configuração (send_config_set) — e um laço que configura cinquenta equipamentos errados em segundos é o pesadelo de qualquer operação. Automação de configuração começa em laboratório, com revisão de outra pessoa e com plano de volta.

    Onde isso é usado de verdade¶

    A Netmiko é a biblioteca de automação por SSH mais usada em Python, com suporte a equipamentos de dezenas de fabricantes; o ConnectHandler e o send_command deste capítulo são exatamente a interface dela. Por cima dela e de outras ferramentas, existem camadas mais altas: o NAPALM oferece funções que devolvem os dados já estruturados e iguais para todos os fabricantes (a mesma ideia de normalização do capítulo 9), e o Nornir roda tarefas em paralelo sobre um inventário inteiro, com o registro de falha por equipamento que este capítulo fez à mão. Uma boa comparação entre elas está no blog da APNIC.

    O coletor deste capítulo — inventário, laço, falha por item, resultado estruturado, relatório — é o esqueleto do projeto final, e de boa parte dos scripts que rodam todo dia em qualquer NOC.

    Erros comuns deste capítulo¶

    Sintoma Causa provável
    a coleta parou no terceiro equipamento a conexão está fora do try, ou falta o except para aquele tipo de falha
    % Invalid input detected na saída o comando está escrito errado ou não existe naquele sistema
    ValueError: not enough values to unpack no parser uma linha da saída tem menos colunas (o cabeçalho, uma linha vazia) — pule-a antes
    o estado saiu "administratively" a linha foi quebrada com split() sem maxsplit, e o estado tem espaço
    sessões presas no equipamento a conexão não foi fechada; use with
    a senha aparece no repositório a credencial foi escrita no código; use variável de ambiente

    Resumo¶

    • ConnectHandler(...) abre a sessão; send_command devolve a saída como texto; with fecha sozinho.
    • **dicionario passa cada chave como argumento com nome.
    • A saída é texto: splitlines, split(maxsplit=...) e rpartition a transformam em dado.
    • A função de coleta nunca levanta erro: cada falha vira um resultado com o motivo.
    • Um resultado no mesmo formato para sucesso e falha deixa o relatório simples — e o pandas faz o resto.
    • Com equipamento de verdade, muda o import; e comece sempre pelos comandos que só leem.
